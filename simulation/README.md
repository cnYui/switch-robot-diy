已在本机安装独立 Python 环境 simulation/.venv。双击“打开实时仿真.cmd”即可使用。1=开，0=关，S=停止按压并退回，P=切换自动循环；鼠标可以旋转、平移、缩放。程序使用 MuJoCo 逐步求解，按压臂与翘板之间通过碰撞接触传力。关闭窗口即可退出。

results/index.html 是测试报告，内含视频、曲线、184 个场景的结果说明和可拖动时间的记录。results/mujoco_full_test.mp4 是 MuJoCo 原生渲染器输出的测试录像，按 0.6 倍速度回放已计算轨迹。results/validation.json 记录测试断言、故障识别和步长收敛证据。results/suite.json 是完整参数和结果。cases 中的失败用例是故意注入的故障，不能将 184 个场景解释为 184 次实物通过。修复前（V0.5）的 116 场景结果保存在上一级目录的 simulation_results_v05_archive。

模型保留旧 STL（arm_v01）、旧动画几何（arm_v02）与 V0.5 候选件三种版本。旧 STL 中立时与翘板穿入约 0.216 mm；独立 Blender 原网格精确交集为 2.677 mm³。动画几何把最低点从 10.5 mm 抬到 12 mm，但垫座在约 5° 转角处仍与支架有极小交集。刚体模型在这里受阻。实际打印公差和材料弹性会影响实物表现，楔紧产生的巨大刚体反力不能用作塑料强度预测。

V0.6 修复（2026-11-12）。仿真暴露的问题和对应修改：

1. 旧 STL 中立预压、动画版边缘干涉：正式按压臂改用已通过 Blender 精确交集检查的版本，并换成 V0.6（arm_v06）。V0.6 在 ±20° 全范围内与支架交集为 0，中立时与翘板交集为 0。旧 STL 归档到 mechanical/archive，文件名带 DO_NOT_PRINT。
2. 按压角窗口窄、安装高度偏低 1 mm 退不回：指杆下端抬高到 17.5 mm，下面粘 4×7×5.5 mm 弹性压垫（泡棉或 TPU，外购，不在 STL 内），模型中压垫装在弹簧滑块上（pad_stiffness_n_per_mm=2、pad_travel_mm=2.5）；支架整体垫高 1.0 mm（每个安装脚下叠两片 0.5 mm 的 M3 平垫圈，mount_dz_mm=1.0），中立空隙从 1.1 mm 增至约 2.2 mm；名义按压角改为 17°。同类的高度×按压角扫描里，修复前即使选最好的固定按压角（11.4°），可通过的安装高度偏差范围是 -0.5 ~ +1.5 mm（2.0 mm 宽）；V0.6 在名义 17° 下是 -1.5 ~ +1.5 mm（3.0 mm 宽，以名义垫高为中心），范围放宽约 1.5 倍，不是数量级的改善，-1.5 mm 一端峰值力已达 5.4 N、接近人为设的 6 N 限值，所以实物上仍应把安装高度控制在 ±1 mm 以内。扫描图是 results/height_stroke_map.png，修复前对照是 results/legacy_v05_height_stroke_map.png。正常翻转的峰值接触力从 4.64 N 降到 3.70 N；高度偏低 1 mm 时不再退不回。32 组组合扰动（含 ±1 mm 安装高度、±1.5° 按压角、±20% 压垫刚度、2 ~ 3.8 N 翻转阻力）全部通过。
3. 代价：压垫最大弹簧力约 2 N/mm × 2.5 mm = 5 N，翻转阻力峰值 4 N 的开关仍可翻转，5 N 时压垫压到底（v06_switch_beyond_pad_capacity，PAD_BOTTOMED_OUT）；9 N 的硬开关仍翻不动，舵机堵转力矩约 0.1765 N·m，这一项没有靠改设计解决，只能靠量到真实开关力后选舵机。
4. 断电不回中：没有回位弹簧时，压垫弹簧只能把臂推到刚脱离接触的位置（v06_power_loss 仍报 NO_RETRACTION_WITHOUT_POWER，这是预期的）。加 0.05 N·m/rad 的回位弹簧后臂回中（v06_power_loss_with_return_spring，return_spring_nm_per_rad=0.05），对正常翻转力几乎没有影响。回位弹簧还没有进 CAD。另外模型里的舵机反向转动阻力只有 0.7 mN·m，而且 MuJoCo 的关节摩擦偏软，不能据此判断真实 SG90 断电后能不能被弹簧带回，需要在实物上测量。
5. 状态读回的目标角：之前 PWM 超时回中后，state 里的 target_deg 仍显示最后一次指令（例如 4.5°）而臂已经回中。现在报告舵机实际跟随的目标，verify_interfaces.py 增加了对应断言。这不影响接口测试原来的结论：单次 PWM 只保持 250 ms。

V0.6 同样没有实物标定：压垫刚度、行程、翻转阻力、舵机力矩、摩擦都是假设值；压垫弹簧刚度尤其需要用实物压垫测量，如果实测明显偏离 2 N/mm（建议范围 1.5 ~ 2.5），请重跑 experiments.py 看窗口有没有变窄。

碰撞体按原 CAD 构成拆分：按压臂为横梁、两根指杆和两块垫座，支架保留底板、侧壁、安装脚和支撑，底框保留真实中间空隙。碰撞近似忽略螺丝/绑带孔与外部倒角，倒角处最大保守填充约 0.7 mm；按压垫座和指杆的主要尺寸按 CAD 设置。质量和转动惯量来自原封闭网格，再乘以假定的 PETG 密度 1240 kg/m³ 和 0.55 有效质量系数。真实印件需要称重校准。

parameters.json 中的舵机采用 SG90 量级：假定堵转力矩 0.1765 N·m、空载转速约 8.73 rad/s，并包含速度相关力矩、输入死区和近似回差。厂家同名舵机和仿制品规格不同；当前硬件没有被识别为某一具体型号。这些数值不代表已测得用户舵机性能。

翘板采用以 ±3.5° 为稳定位置的四次势能模型，峰值翻转阻力暂设为 3 N、参考作用臂长 24 mm。被动转矩公式为 tau=k*q*(1-(q/q0)^2)，k=峰值转矩*3*sqrt(3)/(2*q0)。控制器不读取翘板角度来指定翻转。对照用例关闭碰撞后，按压命令不能使开关翻转。实际开关需要测量力—行程曲线，再替换这条假定曲线。

model.py 中的 RobotSimulation.step 实现被动阻力和舵机有限力矩；controller.py 只按时间和用户指令生成 50 Hz PWM。没有将目标位置直接写给翘板。桥接与控制器报告“动作序列结束”，不会声称真实开关状态已确认。真实设计当前没有位置或电流传感器。

回中验收同时检查实际臂角是否位于声明的死区与回差误差预算内，以及固定臂位置后翘板两个稳态的最小几何空隙是否至少为 0.30 mm。不能用精确零角度来代替机械空隙，也不能因为角度接近零就忽略接触。6 N 是本次人为设置的设计测试限值，不是实测开关、舵机或塑料承载极限。

默认时间步长 0.125 ms、PGS 求解器和金字塔摩擦锥。使用 0.0625 ms 再算后，正常用例峰值力变化约 1.2%、臂角最大差约 0.05°、翘板角最大差约 0.19°。所有具名用例的 MuJoCo 数值警告均被捕获并检查。更粗时间步长不适合作为力峰值依据。

正式 PCB 导出、元件三维库模型、壳体、打印底框、支架、舵机和按压臂在同一个 MuJoCo 场景。PCB 为静态装配显示，未进行电路求解。板底按原生导出的实际基板坐标与 11.9 mm 支撑面匹配，避免假定组件原点就是板顶面。部分元件原始引脚太长，会进入盒底；展示模型假定焊后引脚在板底以下保留 1.5 mm。顶点包含检查没有发现修剪后顶点进入盒体或盒盖；这不是完整三角面相交或制造公差证明。C1、F1 库外形高度近似，实际主控开发板、插头及线材弯曲空间仍未核验。

运行 python bridge.py 可在 127.0.0.1:8711 启动本机仿真接口。每行一个 JSON：{"type":"command","value":"ON"}、{"type":"command","value":"OFF"}、{"type":"command","value":"STOP"}、{"type":"pwm","microseconds":1500}、{"type":"state"}。verify_interfaces.py 实际启动独立服务进程并使用 TCP 套接字核对 ON/OFF、非法指令、PWM、超时回中和状态回读。当前没有打开串口、运行 ESP32 固件二进制或驱动任何真实硬件。

模拟器设置的 250 ms PWM 超时回中属于本次虚拟驱动策略，真实舵机不会因此自动获得同样策略，后续需在真板固件中实现并验证。断电用例显示按压臂不能保证退回，应作为真实设计限制保留。

复现顺序：安装 requirements.txt；在 Blender 后台运行 export_cad.py；运行 prepare_collision.py 和 prepare_pcb_assets.py；运行 experiments.py、verify_interfaces.py；在 Blender 后台运行 verify_cad_intersections.py；运行 make_report.py 和 render_results.py。这些脚本要在 simulation 目录里直接用 .venv 的 python 运行（不要加 -I，否则找不到 model 模块）。已经提供的 assets、results 可直接使用，无需重新导出 CAD。结果 XML 包含几何、关节和执行器，完整运行还需要 model.py 的被动阻力与驱动，因此单独打开 XML 不会复现整套动作。

这次没有覆盖 Wi-Fi/蓝牙与米家协议、电压电流与启动压降、保护器件热行为、真实 MCU 二进制、打印件弹性/屈服/疲劳、胶带与螺丝的固定强度。需要在实物上测量舵机、翘板和打印件参数后校准，再用少量实物试验核对预测。
