# 用家里的工具实测，标定仿真参数

仿真里舵机、电源和开关的参数目前都是按公开规格估的假设值。这一页说明怎么用 USB 电流表、万用表、手机慢动作视频和厨房秤量几项关键数据，填进测量表，再由平台拟合出模型参数、写回 project.yaml。整个过程不需要示波器，一个下午能做完。

## 准备

需要的东西：一个 USB 电流电压表（俗称 USB 测试仪、“USB 表”，能显示电压和电流即可），一块万用表（量电压用，表笔能插进杜邦头背面），一个能慢动作录像的手机（240 fps 最好，120 fps 也能用），一个厨房秤（精度 1 g），一把尺子或游标卡尺，一个 USB 转杜邦线的取电小板或剪开的 USB 线，两只功率电阻（例如 10 Ω 5 W 和 3.3 Ω 10 W 的水泥电阻），一个舵机测试器或者能输出固定脉宽的开发板固件。

把 template.yaml 复制一份，比如 my_bench.yaml，边量边填。每个量都写成 value 和 unc 两项：value 是读数，unc 是你估计的不确定度（大约一个标准差，单位和读数相同）。不确定度不用算得很精确，按“读数大概会差多少”估就行，例如 USB 表电流跳动在 0.60 到 0.64 A 之间，就写 value 0.62、unc 0.02。没量的项保留 null，拟合时这些项对应的参数会保持原来的假设值，并在报告里写明原因。

targets 段写这些测量对应 project.yaml 里的哪个对象：actuator 是舵机（示例里是 servo1），source 是给舵机供电的电源（台架接法下是 usb，即电脑 USB 口），element 是开关的双稳态弹簧（rocker_detent）。

## 一、舵机堵转电流、供电掉压和空载电流

接线：电脑 USB 口 → USB 表 → 取电小板 → 舵机红黑线；舵机信号线接舵机测试器或开发板。ESP32 先不要和舵机共用这个口（共用的情况在第五项单独观察）。

空载静止电流：给一个固定脉宽（例如 1500 µs），舵机转到位后不动，不加任何负载，读 USB 表的电流，填 servo.idle_current_a。这是舵机控制电路自身的耗电，一般只有几毫安，USB 表分辨率不够时就写 0.005 左右、不确定度 0.003。

堵转：先让舵机停在一个位置，用手捏住舵盘（或者把舵臂顶在桌边），再把指令改到另一个角度（例如从 1500 µs 改到 2000 µs），舵机会用力推但转不动。这时读两个数：USB 表的电流填 stall.current_a，万用表表笔插在舵机插头背面量红黑之间的电压，填 stall.v_servo_v。USB 表自己显示的电压也顺手记在 stall.v_meter_v，只作参考。堵转电流大、发热快，每次只堵两三秒，读完立即松手或把指令改回来；SG90 这类塑料齿轮舵机长时间堵转会烧电机或打齿。

堵转力矩（可选，但强烈建议做）：把舵机固定住，舵臂水平伸出，下面垫着厨房秤，让舵臂末端压在秤上一个小垫块上。先去皮，再给一个让舵臂往下压的指令，舵机堵转时读秤的克数，填 stall.torque.force_g；用尺子量舵机输出轴中心到舵臂压在秤上那一点的水平距离（米），填 stall.torque.lever_m。这一项同时记下当时的电流和舵机端电压（就是上面的堵转测量）。没有这一项，平台只能拟合电机电阻和反电动势常数，齿轮效率会保持假设值。

扫动电流（可选）：让舵机在两个角度之间来回摆，不带负载，摆动周期固定（例如每 0.5 s 换一次方向，一个来回 1 s），读 USB 表显示的平均电流，填 sweep.current_a、sweep.angle_deg（摆动幅度）和 sweep.period_s。平台用它估算齿轮和电机的空载摩擦（写到舵机关节的 frictionloss）。USB 表一般每秒刷新一次左右，周期取 1 s 或更长读数会稳一些。

齿轮间隙和输出柔度（可选）：舵机通电并保持一个固定脉宽，用手指轻轻来回拨舵臂，舵臂能自由晃动、电机还没有反应的那段角度就是间隙，在舵臂后面贴刻度纸，用手机拍下两端位置读角度，填 backlash_deg。柔度：舵臂水平伸出压在厨房秤上，先轻轻接触刚好消除间隙，记下角度，再让舵机用力（或往下压舵机本体）到秤读数为某个值，记下舵臂多转过的角度，填 compliance 的 force_g、lever_m、deflection_deg，平台按力矩除以角度得到扭转刚度。这两项默认在仿真里是关闭的（间隙 0、刚性连接），填了才会打开；打开后建议把舵机关节的 armature（电机转子折算惯量）移到 actuators.servo1.gear_inertia_kg_m2，免得重复计算。

## 二、舵机速度（手机慢动作）

舵机只装舵盘、不带负载。手机开 240 fps 慢动作，对准舵盘拍，画面里最好有一个量角器或者在舵盘后面贴一张画了刻度线的纸。让舵机从一个位置转到相距 90° 的另一个位置（例如脉宽从 1000 µs 切到 2000 µs，按 11.1 µs/° 就是 90°），拍下来。

在相册里逐帧看：记下舵盘开始动的那一帧，再记下它到达终点（离终点 2° 以内，肉眼看就是“停住了”）的那一帧，两帧之差除以帧率就是转动时间，填 moves 第一项的 time_s。不确定度大约是 1.5 帧，240 fps 时写 0.006 s。同时用万用表量一下舵机插头处转动前的静止电压，填 v_servo_v。角度不是 90° 的话把实际角度填进 angle_deg。

建议在较低的电压下再拍一次（moves 第二项）：例如在舵机红线上串一只 2.2 Ω 左右的电阻，或者换一个电压较低的电源，让舵机端电压降到 4.2 V 左右再拍。原因是：舵机慢，可能是电机本身的转速限制（电压低就更慢，基本成比例），也可能是舵机里的控制电路限制了速度（电压低了几乎不变，常见于数字舵机）。只有一个电压时这两种情况都能解释数据，平台会在报告里提示；有两个电压，平台就能分辨，并在后一种情况下拟合舵机的速度上限 max_speed_dps。

## 三、开关翻转力（厨房秤或推拉力计）

把开关面板平放在厨房秤上（墙上的开关可以拆下来，或者用一个同型号的开关），去皮。用一支笔头或小木棍，竖直往下压翘板的一端，慢慢加力直到它“啪”地翻过去。用手机录下秤的读数，回放找到翻转前一刻的最大读数，填 switch.force_peak_g。最好重复五次左右，把每次的读数写成列表填到 force_peak_g_trials，平台会取平均并用离散程度估不确定度。有推拉力计的话直接读峰值，换算成克（1 N 约等于 102 g）。

用尺子量从翘板转轴（翘板中间那条转动线）到笔头压的那一点的距离（米），填 press_lever_m。开关模型的峰值力是按另一个力臂（project.yaml 里 rocker_detent 的 lever_m）定义的，平台会按力矩相等自动换算，所以压在哪里都可以，只要距离量准。

翘板行程：翘板从一端翻到另一端转过的总角度填 travel_deg。可以用手机的水平仪应用贴在翘板上分别读两端的角度再相减，也可以量压点处翘板表面的高度变化（毫米）填 travel_mm，再把这个压点到转轴的距离填 travel_lever_m，平台换算成角度。平台把总行程的一半作为两个稳定位置的角度 stable_deg。

可选：翻转过程中力最大的时候，翘板离起始位置转过了多少度，填 peak_at_deg_from_rest。仿真的双稳态弹簧曲线形状是固定的（峰值在起点到中点的约 42% 处），这一项只用来检查模型形状是否合理，不参与拟合。

## 四、USB 口或电源适配器的输出特性

开路电压：USB 口只接 USB 表（或者接取电小板但不接负载），读电压，填 supply.open_circuit_v。

带载电压：在取电小板的 5V 和 GND 之间接一只已知阻值的功率电阻，读电流和电阻两端的电压（用万用表在电阻上量，而不是 USB 表的读数，这样线缆和接头的压降也算进电源内阻里，和仿真的建模方式一致），填到 supply.points 里一项，写上 r_load_ohm。10 Ω 大约 0.5 A，3.3 Ω 大约 1.5 A（如果电源不限流的话）。第一项里舵机堵转的那组电流和电压也可以作为一个点填进来，这一项不写 r_load_ohm，平台会把测到的电流当作负载。

是否限流：如果接小电阻后电流卡在某个值上不再增加，电压却掉得很厉害（例如 3.3 Ω 时电流只有 0.9 A、电压只有 3 V 左右），说明电源进入了限流；有的电脑 USB 口会直接断电再恢复，USB 表会闪一下。看到这种现象就把 current_limit_seen 写 true，并把那一组读数照实填进 points。平台用仿真里的电源模型（电压源、内阻、限流）同时拟合各点，得到 v、r_ohm 和 i_limit_a。如果所有点都没有进入限流，平台只能知道“限流值至少是这么大”，会在报告里说明并保留原来的假设值（原值比实测电流还小时，会提升到实测电流作为下限）。

功率电阻会很烫，接上读完数就断开，放在不怕烫的地方，不要用手摸。不要把 USB 口直接短路。

## 五、ESP32 欠压重启观察（可选）

按台架接法把舵机红线接在开发板的 5V 引脚上，和 ESP32 一起由同一个 USB 口供电。打开串口监视器，让舵机堵转两三秒，看 ESP32 有没有重启（串口会重新打印启动信息，复位原因是 BROWNOUT 或 POWERON）。在 brownout 段填 esp32_reset（true 或 false）、servo_node（舵机当时接的是工程里的哪个节点，台架接法是 usb5v），condition 里用一句话写清楚当时的条件。

平台不会用这一项拟合参数，而是用拟合后的电源和舵机参数算一遍稳态堵转，看 ESP32 供电是否会跌到欠压阈值以下，再和你的观察比较。如果仿真说不会重启而实物重启了，通常说明问题出在平均值模型没有的瞬态上（舵机启动瞬间的冲击电流、舵机内部 PWM、USB 表的平均作用），或者实物接线和 project.yaml 不一样。

## 拟合和写回

填好以后运行拟合（MCP 工具 fit_measurements，或者在工程目录下用 Python）：

    python -c "from emcosim import fit; print(fit.format_report(fit.fit_measurements('.', 'measurements/my_bench.yaml')))"

报告列出：每个参数的新值和不确定度、哪些 project.yaml 路径会改（旧值到新值）、哪些参数因为数据不够保持原值以及原因、每个测量量在拟合前后的模型预测和残差（z 是残差除以不确定度，绝对值小于 2 左右算吻合），以及欠压观察的对比。确认无误后加 apply=True 写回 project.yaml，平台同时在 calibration.measurements 下记录来源文件和每项改动，方便用 git diff 审查。标记为 example_data 的测量表（例如本目录的 example_sg90_usb.yaml，里面全是编造的示例数值）不会被写回。

舵机的齿轮比从外部量不出来，只有“反电动势常数乘齿轮比”是确定的，所以齿轮比保持原值，反电动势常数按它换算。

## 和实测波形对比

如果有示波器或带记录功能的万用表，可以把实测的电压或电流随时间变化导出成 CSV（第一列时间，后面是数值，要有表头，见 trace_template.csv），和某次仿真运行的同名信号比较，得到均方根误差：

    python -c "from emcosim import fit; print(fit.compare_run('.', None, 'measurements/usb_stall.csv', 'node.usb5v.v', time_unit='ms', align=True))"

run_id 写 None 表示最近一次运行。align=True 会在正负 0.5 s 内自动找时间偏移，因为示波器的触发时刻和仿真的时间零点一般对不上。
